# Checkpoint: daab — 2026-07-01 (session 2)

## What was done

- **Reproduced and debugged `backlog/sse-block-ordering-bug`** (P1, last open item).
- **Root cause confirmed (Go data race):** `SSEStreamService.Stream()` in `ennam.kg.go/internal/service/sse_stream.go` ran a heartbeat goroutine and `proxyFromPython` concurrently, both writing to the same `http.ResponseWriter` without a mutex. When the heartbeat fired (every 15s) while the proxy was mid-write, bytes interleaved on the wire, corrupting SSE events. Clients dropped corrupted `block_start` events → blocks appeared "out of order" (earlier blocks missing).
- **Fix applied (Go):**
  - Added `lockedResponseWriter` struct (wraps `http.ResponseWriter` with `sync.Mutex` on `Write` + `Flush`).
  - Added `heartbeatInterval time.Duration` field to `SSEStreamService` (zero → defaults to 15s; used in tests for short intervals).
  - Modified `Stream()` to wrap `w` in `lockedResponseWriter` before passing to heartbeat goroutine and `proxyFromPython`. Both goroutines now use `lw` — concurrent writes are serialised.
  - File: `ennam.kg.go/internal/service/sse_stream.go`
- **Fix applied (Frontend):**
  - `sse-handler.ts` `onBlockContent` callback type had `token?: string` but wire format sends `content`. Fixed type to `content?: string`.
  - `use-thread-messages.ts` read `data.token` in `onBlockContent` handler — changed to `data.content`. This fixes the reconciliation fallback for markdown blocks that missed individual content tokens.
  - Files: `ennam.kg.next/src/lib/streaming/sse-handler.ts`, `ennam.kg.next/src/hooks/use-thread-messages.ts`
- **Tests added:**
  - `ennam.kg.go/internal/service/sse_stream_race_test.go` — two new tests:
    1. `TestStream_HeartbeatRace`: drives 5 blocks with 1ms heartbeat interval; `-race` confirms no data race post-fix.
    2. `TestStream_HeartbeatDoesNotCorruptSSEEvents`: heartbeat fires during block streaming; verifies no heartbeat appears between `event:` and `data:` lines.
  - All tests pass: `go test -race ./internal/service/` ✓
