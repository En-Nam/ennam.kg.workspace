# Checkpoint: claude — 2026-08-05 (LAAM: Q12 laam_query_audit misrouting — root-caused and fixed)

Follow-up to `mem:checkpoint/claude-2026-08-05-g5-proactive-redesign`. User asked which of the 12 demo questions still need work; answered Q5 and Q12. This entry covers Q12 (R1's earlier prompt-only fix had regressed/was never reliable).

## Investigation
Probed Q12 voice 4x before any new fix: **3/4 runs called `laam_query_audit`** (LAAM's own internal audit-log tool) at least once, **1/4 exclusively** (never touched DAAB at all). ALL 4/4 final answers were wrong or incomplete — critically, even the run that DID eventually call the real DAAB tool still concluded "no data" from its earlier `laam_query_audit` exploration, never revising its answer from the later correct result. This showed R1 (the pure prompt-text steering rule from `mem:checkpoint/claude-2026-08-05-daab-metric-ambiguity-clarification`'s session) is not reliable enough alone — the model anchors on its first (wrong) exploration and a generic "call the query tool" nudge doesn't override that anchor.

## Fix (2 iterations, both in `orchestrator.ts`)
1. **Named tool name** (not hardcoded/env-driven, since `laam_query_audit` is LAAM's OWN internal tool — `Tool.name` in `tools/laam/query-audit.ts` — not a connector's, so referencing it directly doesn't violate the "don't hardcode connector tool names" rule that governs `dataFetchTools`/`TOOL_DRILLDOWN_PAIRS`). Did NOT import the tool module directly (would drag `@/db`/drizzle-orm into `orchestrator.ts`, breaking the "no module mocking needed" premise `orchestrator.test.ts` relies on) — used a literal string constant instead, same idiom as the existing `"web_read"` literal in this file.
2. Track `calledAuditTool` alongside the existing `calledDataFetchTool` (G5 state). When G5's nudge condition fires (either the reactive or the new proactive branch from the prior session) AND `calledAuditTool` is true, swap the generic `DATA_FETCH_NUDGE` for a specific one.
3. **First cut** (`AUDIT_MISUSE_NUDGE`, a plain string): explained the tool's real scope, told the model to call a real data-source tool. Retested 4x: improved from 0/4 → 2/4 correct, but 2/4 STILL failed — those runs got the nudge, then called `describe_table` AGAIN (further exploration) instead of the actual query tool, burning the remaining round budget.
4. **Second cut** (`auditMisuseNudge(dataFetchTools)`, now a function): lists the ACTUAL configured data-fetch tool names inline (`Array.from(dataFetchTools).join(", ")` — pulled from the same `dataFetchTools` Set already threaded through for G5, no new config needed) and explicitly forbids further exploration ("KHÔNG dò thêm cấu trúc bảng nữa, KHÔNG gọi lại laam_query_audit"). Retested **6x**: **0/6 touched `laam_query_audit` as their primary path** — all 6 runs went straight to real DAAB tools. No more "confidently wrong: no data" answers observed in this batch (previously the dominant failure mode).
5. New test in `orchestrator.test.ts`: `laam_query_audit` called → concludes wrong → asserts the SPECIFIC nudge (containing the actual tool name + "KHÔNG dò thêm...") fires, not the generic one, and the model subsequently calls the real tool.
6. `npx vitest run src/lib/agent src/app/api/chat src/lib/chat` → 451 passed both times (after cut 1 and cut 2). `npx tsc --noEmit` clean both times.

## Residual, not chased further (acceptable — different problem class)
- Exact NUMBERS still vary run to run (97 / 229 / 20 records across different retests) — this is the SAME metric-ambiguity class already documented for Q12 in the demo script (multiple valid table/column readings of "after-hours override" and "sensitive activity", no single canonical definition in the schema). Fix #9's metric-clarification mechanism DID fire correctly in one retest (run 4 asked "manager-approved vs override_applied?"). The routing bug (wrong TOOL) is now fixed; the residual ambiguity (wrong DEFINITION, even with the right tool) is a distinct, already-understood, already-documented issue — the demo script's decompose-into-precise-sub-questions approach remains the recommended path for a stable number.
- One run (run 1 of the 6-retest batch) showed a NEW, minor token-corruption artifact: `"lam_query_audit"` (missing the second "a") — a character-DELETION corruption, not suffix-glue or same-length substitution, so none of the 3 existing `sanitizeToolCallName` techniques catch it. Speculatively this may be the model garbling the tool name while trying to express "don't call laam_query_audit" (echoing the new nudge's own forbidding language) into a stray malformed tool_call. Rare (1/6), didn't block the turn (just fell through to the fail-closed write-gate same as any unrecognized name), not fixed — flagging only.
