- Investigated why DAAB projects "Dasin" (`6115fa4b-d6d4-46d6-9617-2cae644d8a0f`) and "Dasin 2" (`e34d142b-da9e-4f17-bda1-88ac32b6cc5b`) had very different edge counts (685 vs 297) despite identical corpora (9 docs, 147 chunks each). - Manually re-ran `POST /api/v1/internal/graphrag/link` for Dasin 2 (admin key from `daab-server` container env `KG_API_KEY`) → 607 edges upserted, similar_to went 1 → 395. Dasin 2 now at 691 total edges, comparable to Dasin's 685.
- **Root-caused and fixed the underlying bug** in `ennam.kg.go`: `ChunkLinkStore.ProjectsNeedingChunkLink` (internal/store/chunk_link.go) used `NOT EXISTS(any similar_to edge)` — a one-shot check. The 5-min `ChunkLinkWorker` (internal/service/chunk_link_worker.go, added 2026-07-13) could catch a project mid-ingest (e.g. only 2/147 chunks embedded), write 1 edge, and then permanently exclude that project from all future auto-relink passes — exactly what happened to Dasin 2 (worker fired 03:54:05, embeddings didn't finish until 04:02:02).
- Fix: replaced the boolean check with a watermark comparison — `MAX(embedding.created_at) > MAX(similar_to edge.created_at)` (COALESCE to `-infinity` when no edges exist yet). `ChunkLinker.Run` is already a full idempotent pass (`UpsertSimilarToEdge` is `ON CONFLICT DO UPDATE`), so re-running it whenever new embeddings appear is always safe.
- Added `TestProjectsNeedingChunkLink_IncrementalRelink` (internal/store/chunk_link_test.go) using the real Dasin 2 incident timestamps. Verified TDD-style: confirmed it FAILS against the old query (git stash the fix, re-run, red), then PASSES with the fix (green).
