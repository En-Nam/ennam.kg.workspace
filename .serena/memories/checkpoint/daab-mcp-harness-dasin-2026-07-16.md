## Findings
1. **❌ RETRACTED 2026-07-16 — this finding was WRONG.** *(Original claim: "`kg_graph_retrieve` is BROKEN — no passage text, `limit` silently ignored, hop-1 expansion discarded", allegedly "independently verified".)* **It is false.** The analyst used **parameter names that do not exist**, and the main session's "independent verification" reproduced the same symptom **using the same wrong parameters** — verifying a symptom, not a diagnosis. **Real contract** (`internal/handler/graph_retrieve.go:49-55`): `query, project_id, result_k, seed_k, per_document_cap, mode, include_snippet`. **There is no `limit`**; snippets are opt-in via `include_snippet` (deliberate token-efficiency design, `service/graph_retriever.go:100`). **Measured with correct params** (`include_snippet:true, result_k:20`): **9 rows, 9/9 with snippet text, `hop_count` values `[0, 1]` (expansion DOES reach output), 6 distinct documents** — vs 5 rows / no text / `[0]` with the wrong params. ⟹ **`kg_graph_retrieve` works; FR-001 is NOT "untested because broken".** Q8's score of 2 is an artefact of tool misuse — re-run before any FR-001 verdict. **The one real defect: the endpoint silently accepts unknown fields** (`limit`, `zzz_bogus`), which is exactly what produced the false diagnosis → fixed by `DisallowUnknownFields` in `docs/superpowers/plans/2026-07-16-harness-findings-fixes.md` Task 2. **Lesson: reproducing a symptom is not verifying a diagnosis — read the API contract before believing a consumer's bug report.**
2. **✅ The concept-dedup fix is confirmed working by a real consumer.** `kg_get_neighbors(ĐẠI TÂN)` returned **exactly 8 documents in ONE call** (Q5=3). **No over-merging** — Đại Tân, its Long An branch, and DAI SHIN stay distinct. `kg_related_documents` IDF ranking works as designed (surfaces auditor BHP idf 1.50 over ubiquitous Đại Tân idf 0.12). Strongest results of the run.
3. **🔴 NEW BUG — `BCTC KIEM TOAN 2023` is entity-orphaned.** Zero concept edges, zero related documents, though its text plainly contains `CÔNG TY TNHH ĐẠI TÂN` (returned verbatim by `kg_search_chunks`). **11% of the corpus — a core audited financial statement — invisible to every entity tool, failing SILENTLY.** Reachable only by chunk search. Per-document extraction failure with no surfaced error.
4. **Retrieval ≠ reconciliation (the important negative result).** The run's most valuable DD finding — **FY2024 closing equity 150,768,676,788 vs FY2025 opening 150,647,665,982 = Δ 121,010,806 VND undisclosed**, plus **~47.8bn equity growth vs 0.8bn PAT** — was found by the analyst doing **arithmetic across two documents**. No tool surfaced/ranked/hinted at it. Even a perfect `kg_graph_retrieve` would only co-locate the numbers.
5. **Residual data quality (gates everything downstream):** duplicate concepts persist for **places/authorities** (`KCX Tân Thuận`/`Khu chế xuất Tân Thuận`; two HEPZA nodes) — the dedup fix covers company names only, and splits silently corrupt IDF. OCR still materially damaging: **PLDL numeral `10.146.508.403` vs its own words "một trăm tỷ…" = 10× wrong**; BCTC2023 renders one figure two ways with different digits; audit partner signature unrecoverable. **2 of 5 "contradictions" found were OCR artefacts.**
