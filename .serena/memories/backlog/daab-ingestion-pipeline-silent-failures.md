# BUG (HIGH) — ingestion pipeline silently produces empty FR-001 substrate

**Found:** 2026-07-13 by a real end-to-end ingest test. Created project **Sala Food** (`b9a4d353-2bd9-458f-a78a-eb3b54998706`), ingested 15 real M&A PDFs (`doc_pdf_test/project_2`) via `POST /api/v1/projects/{id}/ingest/upload` (auto_approve). Every doc reported success (`status=approved`, pipeline log `nodes=1 sections=0 embeddings=0 errors=0`) but produced only 1 document node + a few concepts — **0 document_section, 0 document_chunk, 0 embeddings, 0 similar_to.** This is why FR-001 was empty for Cảng Định An too, and it fails SILENTLY (AGENTS.md Rule 12 violation).

## Three distinct swallowed failures (per-doc, from `daab-worker` logs)
1. **Section create 400 — summary too long.** `create section skip: KG API error 400: summary must be at most 8000 characters (got 9365)` (2×/doc). `decompose.py` sends the full section summary to `create_node`; the Go validator caps it at 8000. Swallowed by `logger.debug("chunk edge skip"/"create section skip")`. ⟹ **0 sections created ⟹ 0 chunks (chunks hang under sections) ⟹ 0 chunk embeddings ⟹ FR-001 substrate can never populate.** Note: `decompose.py:136` already truncates the EMBED text to `summary[:2000]`, but the section NODE create sends the untruncated summary. Fix: truncate summary to the validator limit in the create_node payload.
2. **Worker internal key 403 on new projects.** `extract_upload pipeline errors: ['load architecture nodes: KG API error 403: access denied for project b9a4d353...']` (1×/doc). The worker's KG client key is not authorized for a newly-created project (its project_ids don't include it). ⟹ internal pipeline steps 403 for any project the worker key doesn't already know. Fix: worker/service key must be a global-admin (empty project_ids) OR internal pipeline endpoints must trust the worker without per-project scope.
3. **similar_to linker never auto-triggered.** Confirmed: no call to `POST /api/v1/internal/graphrag/link` anywhere in Python ingest. Even with embedded chunks, similar_to stays 0 until a manual POST. Fix: auto-run the linker after a project's chunk embeddings complete.

## Meta-bug: SILENT (Rule 12 violation)
Every failure is `logger.debug`/`logger.warning` + continue; the pipeline returns `errors=0` and the draft goes `approved`. From outside, ingest "succeeds" while producing an empty graph. **This is why nobody knew the substrate was empty.** Fix: count section/chunk/embedding create failures, surface them in `PipelineBatchResult.failed`, and fail/flag the draft when the core substrate wasn't produced.

## ✅ FIX 1 DONE + VERIFIED END-TO-END 2026-07-13 — commit `9f7f5b7` (`task/implement_docs_sync`)
Root cause was NOT the Python truncation (that already caps `summary[:8000]` code points) — it was a **byte-vs-rune bug in the Go validator** `internal/service/node.go` `validateFieldValue`: it used `len(strVal)` (bytes) against `max_length`/`min_length` while the config documents them as CHARACTER limits. Vietnamese is multi-byte, so an 8000-rune summary (~9365 bytes) was rejected. Fixed: `utf8.RuneCountInString`. Unit test `TestValidateFieldValue_MaxLengthCountsRunesNotBytes` (RED→GREEN). **daab-server rebuilt from branch + redeployed** (`docker compose build kg-server && up -d` — also brings the ef_search fix `fc9afa6` live on :8082).
**Verified on a fresh re-ingest of Sala Food (`b9a4d353…`):** pipeline-done now `sections=1 embeddings=10/11` per doc (was 0/0). DB: document_chunk 124/124 embedded, document_section 65/65 embedded. Linker → 85 `similar_to` edges. **`POST /api/v1/retrieve/graph` returns real cross-document results** (seed_relevance ~0.87 across multiple document_ids). Full FR-001 loop ingest→embed→link→retrieve works on a new deal.

## ⚠️ FIX 3 (worker read 403 on new projects) — NOT a code fix; needs a config action
The worker's `GO_API_KEY` is a SCOPED admin (`{a0000000, 592c7ff7}`). On a NEW project it 403s on the `get_nodes(node_type="architecture")` read in `engine.py:313` ("load architecture nodes"). **This is NON-FATAL noise for document deals** — architecture nodes only exist for CODE KGs; the M&A doc substrate (sections/chunks/embeddings, all writes) succeeds regardless. Proper fix = give the worker a **global-admin key** (empty project_ids) so it can read/act on any project it ingests. That requires creating a persistent global-admin service key (dashboard) + setting the worker's `GO_API_KEY` env + restart — a user/ops action, not a code change. Recommend doing it so the worker isn't scoped to two hard-coded projects. Same root as the read-path override bug `mem:backlog/daab-agent-context-project-resolution-bug`.
