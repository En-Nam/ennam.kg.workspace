LAAMSelf-hosted AI work assistant

Version 1.0 · 2026-09-24
Code baseline LAAM @ 7eb0724
Status: pre-production

LAAM is a self-hosted, multi-user AI assistant for teams. People ask business questions in chat or by voice; LAAM answers them against live data by calling tools on connected systems, and in chat it acts on those systems only after the user confirms each write (scheduled workflows write only through workflow-safe tools, to allow-listed recipients). The same tool layer powers durable, scheduled workflow automations that the AI can draft, test-run and hand back for approval.

What is technically differentiated

  • Code-enforced reliability, not prompt hope. Each failure mode measured in testing (invented records, "success" without a write, retyped tables with errors, empty-result false negatives) has a structural guard in code.
  • Human-confirmed actions. Any tool not declared and trusted as read-only is treated as a write. In chat, the user approves a code-built preview; the confirmed call uses the sealed arguments and its nonce is checked against the audit log.
  • Trace-grounded workflow authoring. The AI must first observe real tool calls; a validator rejects plans that reference anything unobserved; the graph is dry-run (writes mocked, reads real) before it is offered.
  • Durable automation. Every workflow step is journaled; runs resume after a crash; an atomic per-step claim stops a resumed run from re-executing a write.
  • Provider- and connector-agnostic. Five LLM providers (including fully local models) behind one adapter; a generic integration layer lets any Model Context Protocol server plug in at runtime without code (a few model-facing prompt strings still reference one knowledge-graph server's tools; cleanup tracked).
  • Hands-free voice. Streaming self-hosted neural TTS (Vietnamese and English), voice-activity barge-in, tables and charts lifted to a display panel.
  • Measured, not asserted. An offline evaluation harness scores tool choice, arguments, grounding, restraint and write intent across repeated runs against real models.
  • Also an MCP server. External AI agents can read LAAM's monitoring data through personal access tokens.

Security and data posture

  • Self-hosted: data stays on customer infrastructure; a fully local model configuration keeps prompts on-premises.
  • Credentials: AES-256-GCM, per-user derived keys; secrets never reach the browser.
  • Outbound safety: user-added MCP server URLs are checked at connect time against private and metadata ranges after DNS resolution; the web reader uses a hostname blocklist; recipient allow-lists for automated messages.
  • No code execution: the agent can act only through declared tools, enforced by a guard test that fails in the test suite (there is no CI yet).
