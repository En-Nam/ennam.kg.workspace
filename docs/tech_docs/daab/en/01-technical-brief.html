DAAB turns an organisation's live business databases and documents into one queryable knowledge graph, and serves it to AI agents through the Model Context Protocol (MCP) and to people through a web dashboard. Agents can search and cite documents, ask questions of live databases in plain language, remember facts across sessions and, under strict controls, write back.

What is technically differentiated

  • The model proposes, code decides. For agent database questions (MCP/API) the LLM returns a structured query plan, not SQL; the server validates it against the extracted schema and renders parameterised, read-only SQL (a READ ONLY session on PostgreSQL sources) with timeouts and row caps. Ambiguous questions return a clarification instead of a guess. The dashboard's agentic chat mode instead lets the model write SELECT statements, checked by a read-only validator with row caps.
  • Databases become a navigable graph. Schema extraction turns tables, foreign keys and AI-detected implicit relationships into graph nodes that documents and agents can link to.
  • Ingest once, cite exactly. Content-hash deduplication, section and chunk structure with line offsets, and Vietnamese-capable OCR, so agents quote the precise passage.
  • Hybrid retrieval and GraphRAG on PostgreSQL alone, with no separate search or vector engine: full-text and vector arms fused by Reciprocal Rank Fusion, then expanded across cross-document similarity edges.
  • Staged entity resolution. Local blocking, rules and a cross-encoder filter candidates before any LLM check; merges are recorded first and reversible. Internal benchmark: precision 1.000, recall 0.915.
  • Local embeddings, provider-agnostic LLMs. Embedding and reranking run on CPU inside the platform; LLM providers are pluggable with failover and per-function model assignment.

Security and data posture

  • Data stays close: embeddings and reranking run locally; document text is not sent out for embedding.
  • Encrypted credentials: source-database DSNs and provider keys stored with AES-256-GCM, decrypted only at use.
  • Scoped access: hashed API keys with roles and project membership; project-scoped roles; read-only MCP tokens.
  • Safe by default: database writes off unless enabled per source, table-whitelisted and fully audited.
